【系统定义】
Pontis为物理的项目文件夹维护了一个知识图谱，agent可以通过基础的文件命令来访问与物理文件相关的知识图谱逻辑实体。

实体更多的是一个语义概念，通过语义进行索引，总结，因此像是row，具体值这种语义信息不丰富的数据载体不会被识别为实体

每个物理文件都有与之相关的逻辑实体，你可以通过[PhysicalPath]::[LogicalEntity] 来访问相关的逻辑实体

- .db数据库文件相关的实体：包含 .table (表), .col (列), .fk (外键)等。
- 非结构化实体：包含 .chunk (文本分片), .summary (摘要) 等。
- 文件夹等项目文件夹也可以拥有逻辑实体，例如一个DBT项目，文件夹下正常ls展示的是物理文件结构，但是如果ls [项目文件夹]:: 展示的则是文件夹下的逻辑实体（暂时还未实现）




【核心交互协议】
- 类型后缀即语义：所有逻辑实体的名称均带有类型后缀（如 orders.table）。后缀决定了该路径下可用的操作和元数据模板。
- 关系挂载 (Bidirectional Mounting)：若一个逻辑关系涉及两个物理文件（如跨库外键），该关系实体（.fk, .rel）会同时出现在两个物理文件的目录下。




[PhysicalPath]::[LogicalEntity]
- ls 正常情况下是展示目录中的物理文件及其元信息，ls一个物理文件或目录并加::控制符会展示一个文件/目录下的所有逻辑实体（慎用）
- glob [物理文件路径名匹配逻辑]::[逻辑实体名匹配逻辑] 
    - 进行名称检索
- search  [物理文件路径名]::[逻辑实体名匹配逻辑] -q [查询] 
    - 语义匹配逻辑
- grep [Options] "Pattern" [PhysicalGlob]::[LogicalEntityGlob]
    - grep能处理的逻辑实体.table .col .chunk
    - grep应该也能检索元数据，
- meta 查看一个物理文件/文件夹/逻辑实体的元信息
- read [物理文件路径名]::[逻辑实体名] 基本文件read的增强版，可以read逻辑实体的值
- jd 序列化文件查看器
