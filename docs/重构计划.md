# Pontis 寻址重构
所有内容都以知识图谱来组织，所有边都是无向边，

每个节点可能归属于一定数量的命名空间

所有的文件都是节点，且一定归属于命名空间file

通过[命名空间]:[节点名]来访问

通过[节点A名]::[节点B名]来访问节点A的邻接节点B

命名空间可能还包括memory，session，knowledge，domain等等

命名空间负责权限控制、生命周期管理和搜索范围；
后缀负责定义数据结构、类型校验和工具映射。


## 操作符

```
:       命名空间标签（优先级最高，只修饰紧跟其后的实体）
::      沿边遍历相邻节点
/       文件系统路径段（仅出现在文件实体的标识符中）
.suffix 实体类型标识
```

## 实体 ref

```
formula_1.db::drivers.table::points.col      ← 数据实体，从文件沿边遍历
formula_1.db::drivers.table::results.table   ← 通过 FK 边跳到另一张表
knowledge:no_concat.convention               ← 知识实体，knowledge: 标记来源
knowledge:bird_train_q123.few_shot           ← 知识实体
```

`:` 只修饰紧跟其后的实体，不影响后续 `::` 遍历。

## glob


```
glob "*.table"                  → 所有表（全局）
glob "*.db"                     → 所有 .db 文件（全局）
glob "*.convention"             → 所有约定（全局）
glob "*"                        → 所有实体
glob "file:*"                   → 所有文件实体
glob "file:{文件匹配逻辑}"       → 检索对应文件实体
glob "formula_1.db::*"          → formula_1.db 的相邻节点
glob "formula_1.db::*.table"    → formula_1.db 下的表
glob "knowledge:*"              → knowledge 下的实体
glob "knowledge:*.convention"   → knowledge 下的约定
```

## resolve_ref

```
输入 ref
  ├─ 以 "ent_" 开头        → ID 直查
  ├─ 以 "knowledge:" 开头  → 去掉标签，在知识实体中按 :: 拆段遍历
  ├─ 包含 "::"             → 按 :: 拆段，逐段沿边遍历
  └─ 无 "::"               → 全局匹配实体名字
```

# Pontis 寻址重构计划

基于 `系统重构.md` 的设计。目标：支持 `:` 命名空间标签 + `::` 图谱遍历，
现有数据实体寻址零改动。

---

## 核心设计原则

**后缀 = 类型（恰好一个），命名空间 = 来源（0 到 N），两者正交。**

| 维度 | 存储 | 数量 | 用途 |
|---|---|---|---|
| 后缀 (`.table`, `.db`) | 实体名的一部分 | 恰好一个 | 工具映射、类型校验、显示格式 |
| 命名空间 (`file`, `knowledge`) | `_namespaces` 元数据 | 0 到 N | 来源追踪、搜索范围 |

参照：RDF 的 `rdf:type`（恰好一个）+ Named Graph（0 到 N）。

文件实体不需要 `.file` 后缀——`.db` 已是类型标识，`file` 是来源属性。

所有实体类型都支持 `_namespaces` 字段（0 到 N）。
数据实体（`.db`、`.table`、`.col` 等）暂时不加命名空间标签，未来可按需添加。
数据实体之间的父子关系通过图谱边表达，meta 按后缀分类展示所有相邻节点。

**实体 ID 对模型不可见。** `ent_xxx` 仅用于工具间内部传参，
模型只能使用名字 ref（`formula_1.db::drivers.table`、`knowledge:no_concat.convention`）。
所有工具输出（glob、meta、read 等）展示实体名字，不展示 ID。

## glob 表达式解析

glob pattern 不是"有无 `::`"的二分逻辑，而是由 `:` 和 `::` 两种操作符组成的表达式。

### 形式语法

```
pattern  := segment ("::" segment)*
segment  := (namespace ":")? entity_pattern
namespace := identifier | "*"
entity_pattern := glob_pattern
```

`:` 优先级高于 `::`，每个 segment 可以带 0 或 1 个命名空间标签。

### 示例

```
*.table                           → (ns=无, *.table)
knowledge:*.convention            → (ns=knowledge, *.convention)
formula_1.db::*.table             → (ns=无, formula_1.db) :: (ns=无, *.table)
file:*.db::*.table                → (ns=file, *.db) :: (ns=无, *.table)
knowledge:conv1::file:*.db        → (ns=knowledge, conv1) :: (ns=file, *.db)
*:*.table                         → (ns=任意, *.table)
```

### 解析算法

```python
def parse_glob(pattern):
    # 按 :: 拆分（注意不要误拆单冒号）
    segments = re.split(r'(?<!:):(?!:)', ...)  # 需要精确处理
    # 实际实现：逐字符扫描，:: 是分隔符，单独的 : 是命名空间标记

    result = []
    for segment in segments:
        if ':' in segment and not segment.startswith(':'):
            ns, name = segment.split(':', 1)
            result.append((ns, name))
        else:
            result.append((None, segment))
    return result
```

### 执行逻辑

对每个 segment，生成一组匹配的节点 ref。相邻 segment 之间通过图谱邻接边传递：
1. 第一个 segment 的匹配结果 = 候选节点集合
2. 对每个 `::` 后续 segment：从前一集合的每个节点出发，沿边找到邻接节点中匹配的
3. 命名空间过滤：`ns:pattern` 只在指定命名空间的节点中匹配
4. 无命名空间的 segment 在所有节点中匹配

### 重名处理

全局匹配 `glob "*.table"` 可能返回多个同名但不同路径的实体：
```
formula_1.db::drivers.table
card_games.db::drivers.table
```
返回结果包含完整 ref，agent 用完整 ref 调用 meta/read 即可区分。

`meta` 的 ref 必须足够唯一。如果 `meta "drivers.table"` 有歧义（多个匹配），
返回错误提示用更精确的 ref。

## 命名空间

### 命名空间 vs 后缀

两者正交，不合并：
- `*.table` — 在实体名中匹配（类型过滤）
- `knowledge:*` — 在元数据中匹配（来源过滤）
- `knowledge:*.convention` — 两者组合

`table:*` 不能替代 `*.table`：前者匹配元数据，后者匹配名字。
保留两者 = agent 有两种过滤手段。

### 命名空间定义

| 命名空间 | 职责 | 节点示例 |
|---|---|---|
| knowledge | 跨库知识与约定 | no_concat.convention, count_no_distinct.pattern |

### BIRD train 可提取的扩展命名空间

| 命名空间 | 来源 | 提取内容 | 示例 |
|---|---|---|---|
| knowledge | golden SQL 统计 | 写作约定、SQL 模式频率 | `no_concat.convention` |
| knowledge | train evidence | evidence 解释模式 | `strict_formula.pattern` |
| knowledge | train 错误分析 | 常见错误和修正 | `unrequested_filter.convention` |
| domain | train 数据库分类 | 行业术语、代码映射 | `education.SOC_code.term` |
| few_shot | train Q-SQL 对 | 按题型的 SQL 示例 | `ranking_top_n.example` |

`knowledge` 覆盖通用知识，`domain` 覆盖领域特定知识，`few_shot` 覆盖具体示例。
用 type suffix 做细分类，命名空间做大分类。

### 命名空间数量：可变

所有实体的命名空间标签数量为 0 到 N，存储在 `_meta.yml` 中。
数据实体暂时不加标签，知识实体显式标注。

```yaml
# 文件实体（extractor 从文件创建）— 暂无 _namespaces
_entity_name: formula_1.db
# 无 _files — 文件名即路径

# 数据实体（从文件提取）— 暂无 _namespaces
_entity_name: drivers.table
# 父子关系通过图谱边连接 formula_1.db

# 知识实体（从 train 提取）— 有 _namespaces
_entity_name: no_concat.convention
_namespaces: [knowledge]

# 领域知识实体（可能同时属于 knowledge 和 domain）
_entity_name: SOC_code.term
_namespaces: [knowledge, domain]
```

```python
    # namespaces: ["knowledge"] | ["knowledge", "domain"] | None
    # 数据实体暂不传，知识实体显式传入

        meta["_namespaces"] = namespaces
    # 其余逻辑不变（移除 _files 相关逻辑）
```

### find_nodes 重构

```python
def find_nodes(self, pattern):
    segments = self._parse_glob(pattern)
    if len(segments) == 1:
        return self._global_match(segments[0])
    else:
        return self._traverse_match(segments)

def _global_match(self, segment):
    ns_filter, pattern = segment
    candidates = self._all_nodes()
    if ns_filter and ns_filter != "*":
        candidates = [r for r in candidates
                      if ns_filter in self._get_namespaces(r)]
    return [r for r in candidates if fnmatch(self._entity_name(r), pattern)]

def _traverse_match(self, segments):
    refs = self._global_match(segments[0])
    for segment in segments[1:]:
        next_refs = []
        for ref in refs:
            adjacent = self._get_adjacent_refs(ref)
            next_refs.extend(self._match_segment(segment, adjacent))
        refs = next_refs
    return refs
```

### resolve_ref 重构

```
输入 ref（模型侧）
  ├─ 以 "knowledge:" 开头   → 去掉前缀，按 :: 遍历知识实体
  ├─ 以 "domain:" 开头      → 去掉前缀，按 :: 遍历领域实体
  ├─ 包含 "::"              → 按 :: 遍历（不变）
  └─ 无 "::"                → 全局匹配或文件匹配

输入 ref（工具间内部）
  ├─ 以 "ent_" 开头         → ID 直查（仅工具间传参，模型不可见）
  └─ 名字 ref               → 同模型侧逻辑
```

## meta 展示：按后缀分类

meta 展示相连实体时，统一按后缀类型分组：

```
# drivers.table
name: drivers
type: table          ← 从后缀推导
columns: [points, positions, ...]
connected:
  .db:
    - formula_1.db          ← 含 engine: sqlite
  .table:
    - results.table         ← via FK
  .col:
    - points.col
    - positions.col
  .convention:
    - no_concat.convention   ← 知识实体，标注 namespaces: knowledge
```

类型信息沿图谱边传递：`.table` 通过父节点 `.db` 的元数据获得 `engine: sqlite` 等信息，
不需要在 `.table` 上重复存储。知识实体在展示时标注其 `_namespaces`。
