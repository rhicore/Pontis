## 各工具详细说明

### 1. Glob (✅ 完整实现)

**文件**: `tool_use/glob/tool.py`

**接口**:
```python
glob_command(project_path, path_pattern, current_cwd="") -> str
```

**核心能力**:
- 支持 `path::entity` 双层模式匹配
- 先用 Python glob 匹配物理文件，再在匹配到的文件内 fnmatch 匹配实体
- 输出格式: `[name] | [Info]`
- 超过 100 条结果时截断，追加提示信息
- 物理文件按修改时间排序
- 自动跳过 `.git`, `.pontis` 等隐藏目录

**参考CC**: GlobTool 的结构化输入/输出、路径相对化、结果截断(100条)

### 2. Grep (✅ 完整实现)

**文件**: `tool_use/grep/tool.py`

**接口**:
```python
grep_command(project_path, params: dict, current_cwd="") -> str
```

**params 字典支持**:
- `pattern` (必填): 正则表达式
- `path`: 搜索路径 (支持 ::entity 语法)
- `glob`: 文件名过滤
- `output_mode`: "content" | "files_with_matches" | "count"
- `-B`, `-A`, `-C`/`context`: 上下文行数
- `-n`: 行号 (默认 true)
- `-i`: 忽略大小写
- `type`: 文件类型过滤
- `head_limit`: 结果限制 (默认 250)
- `offset`: 偏移量
- `multiline`: 跨行匹配

**核心能力**:
- 优先使用 ripgrep subprocess，不可用时 Python re fallback
- 自动排除 VCS 目录 (.git 等)
- 实体 grep: 支持 `.chunk` 内容搜索
- 三种输出模式完全遵循 CC 格式:
  - content: `path:line:content`
  - count: `path:count` + 总计信息
  - files_with_matches: `Found N files` + 文件列表

**参考CC**: GrepTool 的完整参数集、ripgrep封装、分页逻辑

### 3. Read (✅ 完整实现)

**文件**: `tool_use/read/tool.py`

**接口**:
```python
read_command(project_path, file_path, offset=1, limit=None, sample=None, pages=None, current_cwd="") -> str
```

**核心能力**:
- `path::entity` 语法: `data.db::users.table`, `config.json::ROOT.DICT.users`
- 物理文件: 文本(cat-n格式)、图片、PDF、Notebook、CSV
- 实体读取:
  - `.table`: SQL表数据，支持 offset/limit/sample
  - `.col`: 列数据，pk+value 格式
  - `.chunk`: 文本块内容
  - JSON/YAML 实体: 通过 SerializedVFS 导航
- 默认限制: 文本 2000 行，表 50 行，列 100 行

**参考CC**: FileReadTool 的 offset/limit/pages 参数、cat-n 输出格式

### 4. Meta (✅ 完整实现)

**文件**: `tool_use/meta/tool.py`

**接口**:
```python
meta_command(project_path, path, all=False, property=None, current_cwd="") -> str
```

**核心能力**:
- `path::entity` 语法
- 文件级和实体级元数据查看
- `all=True`: 显示所有字段
- `property=xxx`: 显示特定属性
- 利用现有的 `get_meta_type_config` + `format_meta_output` 格式化

### 5. Lookup (✅ 完整实现)

**文件**: `tool_use/lookup/tool.py`

**接口**:
```python
lookup_command(project_path, file_pattern, type, predicate, output_mode="distinct_count", current_cwd="") -> str
```

**核心能力**:
- DB列值检索: 遍历 .col 实体，按 data_type 过滤，对 DISTINCT 值应用 predicate
- JSON值检索: 递归遍历 JSON 结构，匹配基本类型值和 key
- Predicate 解析: 支持 `>`, `<`, `>=`, `<=`, `=`, `!=` 操作符
- 类型匹配: INT, STR, BOOL, NUMBER, FLOAT, NULL
- 输出模式:
  - `distinct_count`: `path:count:value`
  - `file_count`: `path:count`

**未实现**: LSH 索引 (需要独立的索引构建基础设施)

## 架构设计要点

### path::entity 统一模式

所有工具通过 `utils/path_parser.py` 共享同一套路径解析逻辑:

```python
parse_path_pattern("data/**/*.db::*user*.table")
# -> ParsedPath(file_pattern="data/**/*.db", entity_pattern="*user*.table")

parse_path_pattern("src/**/*.py")
# -> ParsedPath(file_pattern="src/**/*.py", entity_pattern=None)
```

### 工具注册表

`tool_use/__init__.py` 导出 `TOOL_REGISTRY` 字典，供 agent 框架调用:

```python
TOOL_REGISTRY = {
    'glob': glob_command,
    'grep': grep_command,
    'read': read_command,
    'meta': meta_command,
    'lookup': lookup_command,
    'search': search_command,
    'bash': bash_command,
}
```

### 与旧版本的关系

旧版扁平文件 (`glob.py`, `grep.py`, `meta.py`, `read.py`) 仍保留在 tool_use/ 根目录。
新版工具在对应子目录下 (如 `tool_use/glob/tool.py`)。
旧文件的 `__init__.py` 引用已更新为指向新版工具。

如需完全清理旧文件:
```bash
rm tool_use/glob.py tool_use/grep.py tool_use/meta.py tool_use/read.py
```
